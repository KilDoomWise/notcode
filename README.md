# NotCode 🛠️

> **Локальный MCP-сервер для Notion AI**, который даёт агенту полноценные руки на твоём ПК: работу с файлами, точечные патчи, живые персистентные терминалы и Git.

## ✨ Ключевые фичи

* **💻 Изолированные персистентные терминалы** — агент может параллельно запускать dev-сервер, сборку и тесты в разных сессиях, сохраняя `cwd` и состояние.
* **🛡️ Безопасность и автобэкапы** — перед каждым изменением файла создаётся снапшот. В случае ошибки все изменения откатываются одной командой.
* **📁 Работа с файлами и Grep** — чтение, безопасные патчи (`oldStr → newStr`), поиск по файлам и поддержка `.gitignore`.
* **🔀 Управление Git** — удобные обёртки для `status`, `diff`, `commit`, `log` и `branch`.
* **📂 Профили воркспейсов** — переключение между проектами «на лету» без перезапуска сервера.

## 🚀 Быстрый старт

Требуется [Bun](https://bun.sh) v1.1+.

```bash
# 1. Клонируем и устанавливаем зависимости
git clone <адрес-репозитория> notcode
cd notcode
bun install

# 2. Первичная настройка (сгенерирует токен и выведет конфиг)
bun run setup

# 3. Запуск сервера
bun run start

```

> 💡 Команда `bun run setup` выдаст готовый **URL** и **Bearer-токен** — просто вставь их в настройки MCP-клиента в Notion.

## ⚙️ Режимы безопасности

Выбирай уровень свободы для агента:

| Режим | Описание |
| --- | --- |
| `paranoic` | Доступ строго в пределах корня воркспейса. |
| `auto` *(по умолчанию)* | Доступ к корню + явно разрешённым папкам (`workspace_allow`). |
| `bypass` | Полная автономность агента без постоянно всплывающих подтверждений. |

При работе в режиме `bypass` ты защищён постфактум:

* **Снапшоты** — автосохранение файла перед записью (`fs_restore` для отката).
* **Аудит-лог** — полная история всех действий в `~/.notcode/audit.jsonl`.

Сменить режим можно из CLI или прямо через агента:

```bash
bun run src/index.ts mode bypass

```

## 🛠 Набор инструментов (31 Tool)

* `fs_read_file` — чтение файлов с поддержкой срезов строк.
* `fs_write_file` — запись файла.
* `fs_patch_file` — точечный патч (`oldStr` → `newStr`) с dry-run.
* `fs_list_dir` — просмотр директории.
* `fs_search_content` — поиск по содержимому (grep).
* `fs_find_files` — поиск файлов по glob-шаблонам.
* `fs_snapshots` / `fs_restore` — просмотр бэкапов и откат изменений.
* `fs_watch_*` — отслеживание изменений файлов в реальном времени.

* `terminal_open` — открыть новую фоновую сессию.
* `terminal_run` — выполнить команду и получить вывод.
* `terminal_read` — дочитать вывод длинных процессов.
* `terminal_write` — ввод данных в интерактивный процесс (`y/n`).
* `terminal_list` — список активных сессий и их статус.
* `terminal_close` — завершить сессию.
* `terminal_exec` — быстрая одноразовая команда.

* **Git:** `git_status`, `git_diff`, `git_commit`, `git_log`, `git_branch`.
* **Система:** `notcode_status`, `notcode_audit`, `notcode_set_mode`.
* **Воркспейсы:** `workspace_list`, `workspace_use`, `workspace_add`, `workspace_allow`.

## 📜 Команды CLI

| Команда | Описание |
| --- | --- |
| `bun run setup` | Первичная настройка и параметры подключения |
| `bun run start` | Запуск MCP-сервера (SSE + Bearer) |
| `bun run dev` | Запуск в режиме разработки (watch mode) |
| `bun run status` | Статус сервера, текущий режим и лимиты |
| `bun run token` | Посмотреть или пересоздать токен (`--reset`) |
| `bun run audit 30` | Посмотреть последние 30 записей журнала |
| `bun run smoke` | Запустить сквозное тестирование механик |

## 📂 Структура данных

Все системные файлы NotCode хранятся изолированно от твоих проектов:

```text
~/.notcode/
├── config.json       # Настройки, токены и профили
├── audit.jsonl       # Журнал всех выполненных действий
└── snapshots/        # Автоматические бэкапы файлов

```
